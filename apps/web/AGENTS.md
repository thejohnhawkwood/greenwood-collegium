# @greenwood/web

React client. Typed commands are the canonical player interaction.

- Ticket 005 owns the classic transcript, command input, connection indicator, and history.
- The command box stays enabled so a guest can type. Submit still waits for a connected socket. The live client stays on polling and sends a server-issued socket ticket so production play does not depend on a websocket cookie.
- Ticket 009 owns the sign-in gate. Production play requires a session cookie. Guest play remains for local development.
- The student invite count is a number field. Clicks on buttons and fields must not steal focus into the command box.
- After sign-in, an incomplete account sees the character-creation gate. A new student invite is token, then the opening story, then the login, then that gate. The client does not invent species, gender, or name authority.
- Student and teacher sign-in are separate forms. The right-hand teacher pane renders `/auth/classroom` and staff-only `/admin/*` controls. Its Server tab sends `admin defense start`, `admin defense cancel`, and `admin defense status`. It never invents tokens, approvals, restrictions, or game outcomes, and never shows passwords.
- Ticket 015 owns the first-time teacher bootstrap copy. The client still does not invent quest or level outcomes.
- Ticket 010 owns reconnect: ignore already-applied sequences, retry an unacked command with the same id. A new `session-hello` boot id means the process restarted; forget the stored sequence.
- React components never contain game rules. Render validated semantic segments only when they reproduce `event.narration` exactly; otherwise render the plain narration. Entity categories come from the server.
- Do not invent authoritative outcomes from the client.
- The owner retired the separate classic UI requirement in ADR-0028. Keep typed commands, complete plain narration, keyboard access, and non-colour cues. No Tailwind or component library.
- Students wait outside the realm until both names are approved. Rejected submissions return to character creation with teacher feedback; timeouts show a waiting screen until the server allows entry.
- New events must not move a transcript reader who has scrolled up. Show an explicit jump-to-latest button and preserve text selection.
- Illustrations follow `GREENWOOD_ART_DIRECTION.md` and ADR-0041. The locked style is the comic-ink pass: heavy black contour and flat local colour. A smooth painting with no heavy ink fails. Do not replace production files in `public/art/` until a named revision is approved and the task names the surface. The living frame is presentation only. It must not hide command input or invent game text. Presence plates come from the current room only. Conversation overlays must not keep an NPC on the painting after that NPC leaves the scene.
- The compact minimap shows the current floor. The world map can change floors with Up and Down, and can send `up` / `down` when those exits exist.
- The bag is a paper doll. It draws `play-state.slots` as rounded insets with a stylized outline. It does not invent positions. Equip still sends `equip <name>`.
- CombatStage renders `play-state.encounter` as a dimmed modal over the play area: both combatants, health, focus, the lock clock, the server read line when present, the latest combat narration, and buttons that send the projected commands. The modal blocks the map, inventory, quests, skills, and compass. The command box stays available. Overlay FX decorate the latest `combat.action_resolved` event and current foe vitals. A lunge, flinch, cast, guard, retreat, or ward follows that same result. They do not invent damage, focus spend, or legal moves. Skills, under the portrait beside Inventory and Quests, opens the Field Primer. PrimerStage renders `play-state.primer` only. The spread is the page, the school plate is a corner ornament, and nodes are ink marks: one School leaf at a time, with the projected nodes. The client does not invent leaves. Clicking a legal node sends `ink` and that node's name. The Lantern Court noticeboard opens from the Noticeboard in the room. It renders `play-state.noticeboard` only. A Go button sends the projected `seek` command. The quest journal fills the window and shows the projected current step and reward. A duel challenge is a window from `play-state.conversation`; Accept and Decline send `duel accept` and `duel decline`. An outgoing ask is `play-state.duelAsk`. The command dock stays above those windows and shows the current quest step. Bag, Primer, and quest overlays close on Escape. Presence may send `duel <name>`. The world map fills the window and can zoom and pan. Explored rooms are named on the chart when the name has room, and say how to travel. Zoom in to read a cluster. Whole floor shows the level and tucks a name that would cover another. The current room says you are here. A quest destination keeps that name and adds Quest. Fog cells stay untitled; a quest in fog says Quest and does not name the room. A click sends `travel <title>` for an explored room; the server refusal stays on the map. The explored list sends the same command.
